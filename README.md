# useful-dsh-plugins

A short, verified starter kit for [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (`dsh`), plus a browseable catalog of what else is out there.

The ecosystem is large — roughly 12,000 listed plugins, ~6,400 of them installable from npm — so nobody wants another list you cannot read. This repo answers one question: **which handful of plugins are worth installing first, and are they still working?**

## What this is

- **22 plugins**, one per problem, each pinned to an exact version.
- **Checked, not remembered.** `npm run sync` resolves every entry against the live community index: it confirms the plugin still exists, records its newest version and its declared `dsh` engine range, and probes each repository for its last push, star count and licence.
- **A catalog.** [`CATALOG.md`](CATALOG.md) browses all 23 categories. The canonical dataset behind it is the upstream index — a repo should not carry a stale copy of 6,400 records, so `npm run sync` mirrors it to `data/catalog.json` locally for scripting instead of committing it.

## What this is not

Not a security review. A plugin runs inside your harness with your permissions — it can read your files, use your credentials and reach the network. Nothing here has been audited. Installation is verification that a plugin *loads*, not that it is *safe*. Read the source of anything unfamiliar, and prefer a machine that does not hold your keys.

## Requirements

DSH **0.2.2-rc.5** or a compatible `0.2.x` release. Each plugin declares its own engine range; the `DSH engines` column below is copied from the index, and `dsh` refuses an incompatible install rather than breaking your profile.

## Install

### The GUI way

Open **Settings → Plugins → Discover**, add this index source once:

```
https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json
```

then search for any name below and install with one click.

### The scripted way

```powershell
# from this folder, on Windows
./scripts/install.ps1

# one plugin at a time
dsh plugin add dsh-md-studio@1.3.9

# try it without touching your profile
./scripts/install.ps1 -DryRun
```

`install.ps1` reads [`data/verified.json`](data/verified.json) and installs exactly the pinned versions this repo was last verified against — not "latest", which may have moved.

### Reading the table

- **Pinned** is the exact version the last sync saw. Upstream may be newer; `node scripts/sync.mjs` refreshes the whole table.
- **DSH engines** comes from the package's own `engines.dsh`. `any` means it declares no constraint.
- **Health** is a liveness hint, not an endorsement: the licence found in the published package, plus stars and last push once a GitHub token is available (CI has one; a local run without `gh` reports them as unchecked). A recent push does not mean the release you install is the code you would read.
- Pairs under **Install one of each pair** solve the same problem and fight over the same surface. Pick one.

## The full catalog

[`CATALOG.md`](CATALOG.md) is generated from the upstream index and shows the 40 most recently released plugins per category, with the true count for each. For the complete set, use the index directly:

```powershell
# the canonical dataset: ~6,400 installable entries, format 1
curl.exe -sSL -o index.json https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json

# or, after `npm run sync`, the same data trimmed for scripting
node -e "const c=require('./data/catalog.json');const m={};for(const p of c)m[p.category]=(m[p.category]??0)+1;console.log(m)"
```

Because the catalog is generated, **do not edit it by hand** — change [`plugins.json`](plugins.json) (for the starter kit) or the upstream index, then re-run sync.

## How it stays honest

| File | Role |
| --- | --- |
| [`plugins.json`](plugins.json) | Hand-maintained source of truth: the 22 picks and one line on why each is here. |
| [`scripts/sync.mjs`](scripts/sync.mjs) | Resolves the picks, rewrites the catalog and the table above. |
| [`scripts/install.ps1`](scripts/install.ps1) | Installs the pinned set. |
| [`data/verified.json`](data/verified.json) | Last verification run: version, engine range, repo health, install scripts. |
| [`.github/workflows/sync.yml`](.github/workflows/sync.yml) | Weekly sync and a diff check, so a plugin that vanishes or an entry that drifts shows up as a failing run instead of silent rot. |

What the sync checks: the plugin exists in the index · its newest version · its declared engine range · the repository still exists and is not archived · whether its `package.json` runs `preinstall`/`install`/`postinstall` scripts (flagged in the table, because install scripts are the one hook that runs before you have read anything).

What it deliberately does not check: whether the code is safe, whether the description is accurate, or whether the plugin works. Those need a human.

## Contributing

One plugin per pull request, to [`plugins.json`](plugins.json): `name` exactly as the index lists it, a `category`, and a `why` that says what problem it solves rather than how it works. Run `npm run sync` before pushing — a pick that the index cannot resolve fails CI.

Prefer breadth over duplication: if an entry overlaps something already listed, say so with `conflictWith` instead of hiding the overlap.
